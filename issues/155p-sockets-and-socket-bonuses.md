## Current Behavior

Stock. What the data says (read 2026-09-24 from the client files and the
stock world database):

- **How a socket bonus works.** An item row names up to three socket
  colours and one socket bonus. The bonus is an id in the enchantment
  table. The server decides what the enchantment *does*: it reads the
  client file SpellItemEnchantment.dbc plus a database override table
  (`spellitemenchantment_dbc`, loaded over the file). The player's client
  decides what the tooltip *says*, from its own copy of the file. The
  client works out for itself whether the gem colours match.
- **Option 1** (text correct as it is): point a socket bonus at any existing
  enchantment. The catalog, `docs/profiles/socket-bonus-catalog.md`
  (generated by `scripts/generate-socket-bonus-catalog`), lists all 2,595
  usable ones by kind and size, with which are already socket bonuses and at
  what item levels.
- **Option 2** (text from one enchantment, effect from us): take an existing
  enchantment, preferably one no item uses, and override its effect in the
  server's table. Its enchantment type can be "aura while worn" (type 3)
  or "chance on hit" (type 1), naming any existing spell: an absorb shield,
  health every 5 seconds, a hidden passive aura. The tooltip keeps the
  original text.
- **Sockets before Outland:** none that a player can get. The only socketed
  items below item level 80 are monster weapons, test items ("Sword of
  Sockety Goodness", "QA Test Gem Bracers") and Runeblade (a level-55 epic
  with three sockets).
- **Jewelcrafting before Outland (skill 1–299):** no gems at all. It makes
  rings, necklaces, stone statues, figurines, settings, wire and a few
  crowns (skill 20 Delicate Copper Wire … 295 Ring of Bitter Shadows). The
  first cuttable gems are Outland's, at skill 300 (Blood Garnet, Golden
  Draenite and the rest).
- **Level-55 cut gems exist already:** thirteen common gems (Tourmaline
  red, Zircon blue, Amber yellow; +4 Strength, +6 Stamina, +2 mana every 5
  seconds and so on). No recipe makes them; five Burning Crusade gem
  vendors sell them (listed in the catalog).

## Intended Behavior

To be designed with Ritz. The pieces so far:

1. **Option 2, first try:** one item's socket bonus points at an unused
   enchantment whose effect the server overrides with a chosen aura, to
   confirm the text/effect split in game.
2. **Sockets on lower-level gear**, with the item's stats reduced to pay
   for the socket, while a socket still feels worth having for its
   flexibility.
3. **Gems craftable below 300**, so lower-level sockets can be filled.

## Suggested Implementation Steps

1. Option 2 test: pick an unused enchantment from the catalog; add its
   override row to `spellitemenchantment_dbc` (a new install-time SQL
   pair, apply/revert); give one test item a socket and that bonus;
   restart, clear the item cache, socket a gem of the right colour, check
   the tooltip text and the effect.
2. Record in this issue what the server does with each enchantment type
   in the bonus slot (proc chance, aura shown or hidden, stacking).
3. Then the design questions below, one at a time.

## Open Questions

- Which effect for the first option 2 test (an absorb on being hit,
  health every 5 seconds, something else)?
- The socket budget: how much stat to take away per socket, and whether
  the socket bonus counts towards it.
- Which low-level items get sockets (every blue? dungeon loot only? crafted
  gear?), and how many.
- Where low-level gems come from: new Jewelcrafting recipes below 300 (the
  level-55 Tourmaline/Zircon/Amber set is a ready-made tier), drops, or
  vendors.
- Should the tooltip always tell the truth, or can a bonus hide more than
  its text says?
- Set bonuses (an item's set membership is also server data, but the set's
  tooltip list and bonus text are client data): explore, or leave?
