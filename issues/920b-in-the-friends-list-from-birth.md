# 920b - In the Friends List from Birth

## Status
- Created: 2026-10-20
- Phase: 9
- Parent: 920 (legendary friends in every friends list)
- Blocked by: world-edit-to-execute W02a and W02c (the status map's ground and zone records), for the status line only
- Priority: Parked (with its parent, 920: the legends are Blizzard's characters; see 920's "Parked")

## Current Behavior

New characters start with an empty friends list. No legend exists as a
character.

## Intended Behavior

Each legend is a real character on the server, so the stock friends list
and whispers work with no change to the client:

- **The friends list** is the `character_social` table in the characters
  database: one row per (character id, friend's character id, flags, note),
  where flag 1 means "friend". On character creation (ALE's
  `PLAYER_EVENT_ON_CHARACTER_CREATE`, event 1) a row per legend is written
  for **two legends chosen at random** from every sheet in `src/legends/`
  (920a), so its first login shows them. The choice uses the server's own
  random source and is written to the server log with the character's
  name, so it can be checked. Writing the row
  directly skips the friend-adding check that refuses an opposite-faction
  friend (the server's "two-side add friend" permission, which is only
  checked when a player adds a friend by name), so an Alliance player can
  have Broxigar.
- **Being online.** The client only lets a player whisper someone online,
  and the server finds a whisper's receiver among characters in the world
  before any script sees the message (ALE's `PLAYER_EVENT_ON_WHISPER`,
  event 19, receives the receiver as a player in the world). So each legend
  must be logged in. They are characters on one hidden account, logged in
  as playerbots and kept in a closed place no player can reach, never seen.
  The friends list then shows them online, with a zone name.
- **Cross-faction whispers** need the server's two-side chat setting
  (`AllowTwoSide.Interaction.Chat = 1`; the beta profile already sets it,
  in `config/patches/C037-beta-wow-chat-1-survival-settings.sh`).
- **What a player sees** of a legend in the list: its name, level, class
  and zone. Race and class must be playable ones (a character cannot be a
  vrykul or an arakkoa), so Hrothgar and Terokk are characters of some
  playable race whose look nobody sees.
- **Customizing.** Removing a legend is the stock "remove friend" (it
  deletes the row). Adding one back is `/friend <name>`; for an
  opposite-faction legend the server refuses that unless the player's
  account has the "two-side add friend" permission, so either every
  account gets that permission or adding goes through the addon (920d),
  which asks the server to write the row.
- **The status line** ("Questing in Outland", "Married to Medivh"). The
  stock friends list shows, for an online friend, the name of the zone that
  friend is standing in, taken from the client's own zone table. It cannot
  show free text. So **new zone records** are made, one per status line
  (the owner, 2026-10-20: "we will need to add new zone records then"):
  1. **The status map.** A small hidden map of its own, nobody can enter,
     whose ground is cut into patches, each patch marked with a different
     zone record. The client names a friend's zone from the zone record of
     the ground they stand on, so a legend standing on the patch marked
     "Married to Medivh" shows "Married to Medivh" in every friends list,
     stock client included. Changing a legend's status is moving them to
     another patch.
  2. **The zone records** are rows in the zone table (`AreaTable.dbc`), on
     the server and in the client's patch: one per line in every legend's
     status pool (920a), generated from the sheets by a tool, never typed.
     The status map's ground is generated by the same tool, through
     world-edit-to-execute's map writer (W02a, W02c), so adding a status
     line is a sheet edit and a rebuild. The pool is therefore fixed at
     build time: a status the model invents at play time cannot be shown
     this way (open question 2).
  3. **With the addon** (920d), any text can be shown: the addon replaces
     the zone text with a status the server sends by addon message. So an
     addon user can see invented statuses; others see the pool's.

  The server picks a new status for each legend every few hours, or when
  something in their story happens.

  The friend note (a per-row text the *player* writes about a friend, in
  the same table) is not used: it belongs to the player.

## Suggested Implementation Steps

1. An install patch (one `E` step, its own file, header by
   `scripts/add-patch-header`) that creates the hidden account and the
   legends' characters if missing, and records their character ids.
2. The creation hook (Lua, in the profile's Lua directory) that writes the
   friends rows for each new character, plus a one-time step that adds them
   to characters that already exist.
3. Keeping them online: a check at server start and every few minutes that
   each legend is in the world, logging it in as a playerbot if not, and
   saying so in the server log when it had to.
4. Hiding them: the status map (its zone records and ground made by a
   tool from the sheets' status pools), and leaving them out of `/who`.
5. The faction rule in the picker: only legends who can talk to the new
   character (its faction's, neutrals, spirits; 920) are drawn.
5. A test: create a character, log in, read its friends list, whisper each
   legend and see the whisper delivered.

## Open Questions

1. ~~Where are they kept?~~ Answered 2026-10-20 by "we will need to add
   new zone records then": on the status map.
2. **Status lines from the pool only, or also written by the model?** The
   pool is checked in advance and shows in every client; the model (916)
   could write new ones from what the legend has been talking about, shown
   only to addon users.
3. **How big may the zone table grow?** Eleven legends with a few dozen
   status lines each is a few hundred new rows. The client's zone table
   holds a few thousand rows today; the ids need a range of their own,
   shared with 919's new worlds.
