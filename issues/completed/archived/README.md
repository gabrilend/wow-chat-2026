# Archived loose notes

Raw note files that were written straight into the project root, read
later, and sorted into issue files. They are kept here **unchanged** —
same bytes, same missing punctuation, same pasted build errors.

They are not issues and they are not indexed by phase. They are the
input that issues were compiled from. Per the project's own account of
how it is built, LLM transcripts compile into issue files which compile
into source code — these sit at the same layer as the transcripts, one
step before an issue exists.

Nothing here should be edited. If something in one of these files turns
out to have been missed during sorting, the fix is a new or updated
issue, not a correction to the note.

## Why keep them

Two reasons, and the second is the real one.

An issue file is a specification: it states a problem, an intended
behavior, and steps. Getting there means deciding what the note meant,
and a decision can be wrong. Keeping the note means the decision is
auditable — you can read what was actually asked for and check it
against what got written down.

And the notes are written in a voice the issues are not. "they'd follow
beside me. Each one would be configured to look like me, talk like me,
but be beside me" is the whole design of 918, and no amount of
specification prose recovers it once it is paraphrased away.
