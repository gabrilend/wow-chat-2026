# 916k - Chat Prompt Builder and Persona Persistence

## Status
- Created: 2026-06-03
- Parent: Issue 916 (mod-soren-chat)
- Phase: 3
- Priority: Medium (gameplay-relevant guidance ships first; this is the social layer)
- Depends on: 916b (bindings), 916e (worker pool)

## Overview

The social half of mod-soren-chat. Each bot gets a permanent persona —
a personality archetype shaped by race/class/spec plus a short origin
story — stored in the database so the same bot sounds like the same bot
across sessions. When a chat trigger fires (player speaks nearby, bot
enters new subzone, level-up, etc.), this module builds a prompt that
asks the LLM for a single in-character line.

Structurally ports the prompt-design ideas from Hokken's mod-llm-chatter
(see issue 916 context) but in our own Lua, sharing infrastructure with
the guidance layer.

The user has explicitly noted this is not where they want to spend
design energy. The intent is: write it once, leave it alone, bots talk
naturally.

## Current Behavior

No chat layer in mod-soren-chat. playerbots' built-in random chat fires
if enabled, but it's hardcoded English phrases unrelated to any
personality system.

## Intended Behavior

After this sub-issue lands:

- Every bot has a persona row in `soren_chat_persona` with a personality
  archetype and origin story
- New bots (first chat trigger) get a persona generated on demand and
  saved; subsequent triggers read from cache
- `04-prompt-chat.lua` exposes `build(bot, trigger, context)` returning
  a prompt string
- The prompt incorporates: persona archetype, origin story (system
  prompt), race/class/spec, current location, recent events, the
  trigger type (greeting, ambient observation, victory line, etc.),
  and any specific addressee
- Output expected: `{ "text": "in-character line, 1-2 sentences max" }`

## Persona Schema

In `acore_characters_vanilla.soren_chat_persona`:

```sql
CREATE TABLE soren_chat_persona (
    guid         INT UNSIGNED NOT NULL,
    archetype    VARCHAR(64) NOT NULL,
    origin_story TEXT NOT NULL DEFAULT '',
    created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (guid)
) DEFAULT CHARACTER SET UTF8MB4 COLLATE utf8mb4_unicode_ci;
```

The archetype is a short tag like `"skeptical_warrior"`,
`"chatty_mage"`, `"gruff_hunter"`, `"nervous_priest"`. The origin story
is a 2-3 sentence paragraph generated by the LLM at persona creation
time, describing the bot's background in lore-grounded language. Both
persist forever.

## Archetype Selection

Mapping from race + class + spec → archetype distribution. The selection
is deterministic given the bot's GUID (hash GUID → pick from
distribution) so the same bot always gets the same archetype on
regeneration:

```lua
local function pick_archetype(bot)
    local distribution = {
        ["human_warrior"]  = { skeptical = 30, gruff = 30, dutiful = 25, witty = 15 },
        ["nightelf_druid"] = { mystical = 40, calm = 30, curious = 20, dry = 10 },
        ["forsaken_priest"] = { sardonic = 35, scholarly = 25, eerie = 25, kind = 15 },
        -- ... etc
    }
    local key = bot.race .. "_" .. bot.class
    local dist = distribution[key] or default_distribution
    return weighted_pick(dist, hash_guid(bot.guid))
end
```

The distribution tables capture rough lore expectations — Forsaken
priests don't say "Light bless you" cheerfully, Night Elf druids speak
slower than Goblin rogues, etc. Filling out the full per-race-class
table is the bulk of this sub-issue's design work.

## Trigger Taxonomy

Chat triggers (with rough rate guidance):

| Trigger | When | Frequency |
|---|---|---|
| `nearby_player_speaks` | Player says something within 30yd of bot | Respond ~50% of the time, gated by cooldown |
| `entered_subzone` | Bot crosses into a new named subzone | Comment once per subzone entry, no repeats within 10 min |
| `level_up` | Bot dings | Always, once |
| `quest_complete` | Bot turns in a quest | ~30% of completions |
| `ambient` | Periodic, when no other trigger fires | ~10% chance per minute, only when within proximity zone |
| `combat_victory` | Party wins a fight | ~20% of wins, one bot per party speaks |

## Implementation Steps

1. Schema migration: write SQL to create `soren_chat_persona` table.
   File goes in vanilla's SQL migration pipeline (the same C-patch
   system, probably E-series patch).
2. Write `lua/04-prompt-chat.lua`:
   - `build(bot, trigger, context)` returning prompt string
   - Archetype distribution tables (long, formulaic — bulk of file)
   - `pick_archetype(bot)` function
   - System prompt template with persona + origin substitution
   - Per-trigger user prompt template
3. Write persona load/store helpers (probably in
   `04-prompt-chat.lua` or a sibling `04b-persona-store.lua`):
   - `get_persona(guid)` returns cached/loaded persona row
   - `create_persona(bot)` generates archetype, asks LLM for origin
     story, inserts row
4. Wire the trigger detection into ALE event hooks: chat handler for
   nearby speech, zone-change handler for `entered_subzone`, level-up
   hook, quest-complete hook
5. Smoke test:
   - Log in as player, create a bot, trigger each event
   - Verify persona is generated on first trigger and reused
     subsequently
   - Read the database table directly to confirm persistence

## Notes on Porting mod-llm-chatter's Design

We're porting the *design ideas*, not the code. Specifically:

- The race/class/spec → personality archetype mapping concept
- The "speak as inhabitant of Azeroth, not as AI" framing
- The environmental-awareness prompt context
- The trigger taxonomy (with adjustments)
- The persona persistence model

We're not porting:
- The Python service or its prompt code
- The 3000+ subzone description database (use just zone + subzone names
  for v0, expand later if it's worth the table size)
- The `/chatter` and `/llmc` commands (mod-soren-chat has its own
  command family in 916n)

## Open Questions

- Origin story generation: on persona creation, the LLM is called for
  the origin paragraph. That's a real inference call at first-chat
  time. Should the placeholder origin be a generic "you are a
  {race} {class}" until the LLM call completes, with the cached
  origin replacing it on the next trigger? Lean yes.
- Archetype distribution tables: writing all 10 races × 9 classes (or
  even just the cross-product that exists in WotLK) is a lot. Probably
  start with a "default by class" distribution and add race-specific
  overrides only for memorable combinations.
- Per-bot voice consistency: the persona persists, but small models may
  forget the archetype mid-conversation. May need to re-include the
  archetype tag in every prompt, not just at persona-creation. Plan
  for it.
