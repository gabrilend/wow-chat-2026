# buddy-choice.lua

Decides what a buddy is offered and becomes at Sargobras's menu (issue
617b), and what the roster still needs. Pure decisions: touches no server
object, so `sargobras.lua` and the offline test (`scripts/test-buddy-choice`)
run the same code.

## Functions

### `Choice.menu(RC, team, owner_is_dk) -> list of {label, race, class}`
The choices Sargobras offers: every race/class pair legal for `team`
(Alliance or Horde), narrowed to death-knight-only options when
`owner_is_dk` is true.

### `Choice.needed_role(slot, roster, owner_is_dk) -> "tank" | "healer" | nil`
Whether the next buddy (at roster position `slot`) must fill a guaranteed
role the roster doesn't have yet, or `nil` when any pick is fine.

### `Choice.resolve(a) -> race, class`
Turns one menu pick (and any random draw it implies) into the concrete
race/class pair a buddy is created with.

## Where this fits

`RC` is the race/class data table generated by
`scripts/generate-basic-race-class-data` into
`src/lua-basic/data/race-class-data.lua`. `sargobras.lua` calls into this
module for every menu shown and every choice resolved; nothing here reads
or writes a game object directly.
