# buddy-talent-spender.lua

Decides a buddy's talents inside its fixed shape, and draws a new buddy's
shape (issue 617g). Makes no server calls, so the server script
(`../buddy-talents.lua`) and the offline test (`scripts/test-buddy-talents`)
run the same code. Load with `dofile`; returns a table of the functions
below.

## Data it works on

`cls` is one class entry from `../data/buddy-talent-data.lua` (generated by
`scripts/generate-basic-talent-data`; do not edit):

| Field | Type | Meaning |
|---|---|---|
| `name` | string | class name, for messages |
| `trees` | array of 3 trees | left to right, as the client draws them |
| `shapes` | array of 10 shapes | the position is the shape id stored in the roster; never reordered |

A **tree**: `tab` (integer, TalentTab.dbc id), `name` (string), `role`
(string: `"tank"`, `"healer"` or `"damage"`), `room` (integer: points the
tree holds under basic's cap), `talents` (array of talents).

A **talent**: `id` (integer, Talent.dbc id), `name` (string), `row`
(integer 0–10; row n opens at 5n points in the tree), `col` (integer),
`ranks` (integer 1–5), `spells` (array of integers: the spell of each rank),
`dep` (integer: prerequisite talent id, 0 for none), `dep_points` (integer:
points the prerequisite needs), `allowed` (boolean: basic's cap, 155g).

A **shape**: `thirds` (array of 3 integers summing to 3: each tree's share
in thirds), `role` (string, from the tree holding two or three thirds;
one-third each is `"damage"`), `label` (string, e.g. "2/3 Holy, 1/3
Protection").

`held` is a table from talent id (integer) to points held (integer 1–5);
talents with no points are absent.

## Functions

### `read_held(cls, has_spell) -> held`
What a character holds. `has_spell(spell id) -> boolean` is the server's
"has this talent spell" question (for the active spec).

### `plan(cls, shape_id, held, free, rand) -> steps, unspent`
The talents to learn for `free` points (integer), one step per point, in
the order to learn them. `rand(n)` returns an integer 1..n. `held` is not
changed.
- `steps`: array of `{ id, rank, tree, name }`; `rank` is 0-based, as the
  server's learn-a-talent call takes it (one above what is held).
- `unspent`: integer; points no legal talent could take. Normally 0; the
  caller reports anything else.

The order, per point: the shared tree furthest below its share; if none has
room, the overflow tree (the unshared one already holding points, else a
random one). Inside the tree: a legal one-point talent; else the talent
already started; else a starter on a one-pointer's prerequisite chain;
else, when the deepest row the tree has opened holds no points, a talent
from that row; else any legal talent. The reasons are in the file's comments and in 617g.

### `draw_shape(cls, taken, need_role, rand) -> shape_id, filled`
A new buddy's shape. `taken` is a set (shape id -> true) of shapes its
same-class clan-mates hold; `need_role` is `"tank"`, `"healer"` or nil.
Returns a free shape of the needed role when the class has one (`filled`
true), else any free shape (`filled` false). If every shape is taken,
returns nil and a message (cannot happen with seven buddies and ten
shapes).

### `can_fill(cls, role) -> boolean`
Whether any of the class's shapes plays `role`.
