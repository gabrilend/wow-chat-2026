**Where the errors come from**
Some commits in the history were made without a conversation behind them. The
page builder turns each of these into a page where you're the only speaker. For
each file the commit touched, it asks git for a full copy of that file as it was
at that commit. It uses the copy to find the heading above your added lines. It
also asks git for just the added lines, and that second request always works.
Git says "fatal" in three cases where the full copy doesn't exist:

1. **The commit deleted the file.** Example: commit `e42b59e` deleted
   `authserver.conf.bak`, so the file isn't there at that commit. Most of the
   errors are this case.
2. **The "file" is a link to a different repository**, called a submodule entry.
   Example: `modules-beta/mod-ale` in commit `f373d76`. Git stores only a
   pointer to the other repository's commit there, not file contents. When asked
   for contents, git looks for that commit in this repository, doesn't find it,
   and says "bad object."
3. **The file name contains a character outside plain ASCII.** In
   `Playerbot-Addons-and-Sub‐Modules`, the hyphen is a Unicode hyphen. Git's
   list of changed files writes such names in quotes with escape codes. The
   builder then asks for a file literally named with those quotes, and no such
   file exists.

All three cases can only produce added lines with no heading above them on those
pages. A deleted file or a submodule link has no added lines at all, so nothing
is lost.

**The fix:** in the transcript-site builder in your shared scripts folder:
- Skip deleted files and submodule links.
- Pass `-z` to git so file names come back unquoted.
- Send git's messages about missing files somewhere quiet, while still showing
