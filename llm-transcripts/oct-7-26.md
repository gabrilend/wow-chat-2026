**1. Is "entirely on the graphics card" a speed goal or a design rule?** *(still
open from yesterday's optimization work)*

Every bending job now runs on the graphics card: characters, swaying trees and
the ground. Particles (sparks, smoke, spell effects) are the one exception. The
main processor still moves each particle every frame, which costs about 0.3 ms
per frame today.
- **If it's a speed goal:** particles stay on the main processor until spells
  add enough of them for the cost to show.
- **If it's a design rule:** particle motion moves to the card now, even though
  it saves almost nothing yet. The client is then built one consistent way.

**2. Should the custom client stay inside this project, or become a project of
its own?**

It lives inside this project today, in the C client folder in the source tree,
alongside the server's Lua and patches. The main client issue still lists this
as open.
- **Staying here:** it shares issues, phases, transcripts and the build scripts.
- **Moving out:** it gets its own history and phase demos. It could also serve
  other 3.3.5a servers that know nothing about Everland.

**3. Real-time sun shadows, or exactly what the original client draws?**

The original 3.3.5a client never computed shadows live. The ground has shadows
painted into it ahead of time: each patch of ground carries a 64×64 on/off map,
and the shader darkens the ground to 60% where the map is "on". Characters get
only a soft round dark spot under their feet. Both of these are built now.
Real-time shadows would mean drawing the scene a second time each frame, from
the sun's point of view. The renderer would then darken any spot that lies
behind something else from the sun.
- **Exactly the original:** the picture matches the original client pixel for
  pixel, and our picture-comparison tests stay simple.
- **Sun shadows:** trees, buildings and characters cast moving shadows. This
  makes the client deliberately differ from the original.

**4. Should our own server switch off Warden for custom-client accounts, or must
the custom client always pass Warden?**

Warden is the server's anti-cheat check. After login, the server sends the
client a small Windows program. Every 30 seconds it then asks questions like
"hash these bytes of your program at this address" or "is this interface
function the original one?" Right now the server is set to only log a wrong
answer. A client that never answers at all is kicked after 600 seconds. The
current plan is that the custom client answers every check correctly, using the
bytes of the real game program on disk.
- **Always pass it:** the client works on any stock server, but this is real
  reverse-engineering work.
- **Turn it off for our accounts:** much simpler, but the client then only works
  on servers that trust it.

**5. UI gizmo look: plain flat colours, or the game's stone-and-gold borders
drawn flat?**

You asked for a generator that draws the UI pieces (scrollbar, close button,
drag handles), drawn "very flat and possibly shaded."
- **Plain flat colours:** fully our own style, with nothing taken from the
  game's art.
- **Stone and gold drawn flat:** keeps the shapes and colours of WoW's frames
  (carved stone edges, gold trim), simplified into flat shapes and maybe a
  gentle shading gradient.
