## Committing

never another session's work, even if it sits in the same file — and every

## Locks between agents

**Is this file locked? A yes/no answer with no LLM involved:**
- **What already exists.** Every session already keeps a list in RAM of each
  line it writes. The edit hook records it, and the commit tool reads it.
- **What "locked" would mean.** A file is locked if a session that is still
  alive has uncommitted lines in it. A modified file that no session's list
  claims is either a person's work or work left behind by a session that ended.
  For left-behind work there's already a tool that adopts it.
- **Telling whether a session is alive:**
  - When a session starts, a hook writes down its process number and the
    process's start time. Asking the kernel whether that process exists, with
    the same start time, answers yes or no reliably. The start time matters
    because process numbers get reused.
  - After every tool call, a hook stamps the time.
  - When the agent finishes a turn, a hook marks it idle.

  Together these give three answers: **working** (alive, stamped recently),
  **waiting for its person** (alive, idle), and **gone** (no such process).
- **Enforcing it.** A hook that runs before every Edit or Write can refuse an
  edit to a file another session has locked. This would replace the claims list.

**Asking a gone session to commit.** `claude -c` resumes the most recent session
in the folder, which is the wrong one when several sessions run there. `claude
--resume <session-id> -p "commit your changes to <file>"` resumes that exact
session, headless, and lets it commit. This should only be done for a session in
the "gone" state. A live one would end up with two processes writing the same
transcript.

**A "going away" signal.** There's no unloading on the server side, because
nothing stays loaded there. Each request sends the whole conversation, and the
session is a process on this computer plus its transcript file on disk. The
signals that do exist:
- **When a turn ends** (the Stop hook): this can make the agent continue, for
  example "you have uncommitted lines older than 10 minutes, commit them first."
  That's going idle with grace.
- **When the session exits** (the SessionEnd hook): this runs a script, but the
  agent can't act anymore. It's good for marking the lock released or stale.
- **Before compaction** (the PreCompact hook).
- **Nothing fires** on a crash, a kill, or a reboot. That's why the liveness
  check above can't depend on goodbyes.
